## 功能

- 從高層級漫畫目錄自動建立「系列 → 章節」樹狀列表。
- 系列依更新時間由新到舊排列，章節依最小章號由小到大排列。
- 顯示章節狀態、資料夾大小、更新時間及順序編號。
- 選擇父系列或單一章節後，將指定範圍圖片連續編號並整合成 `Chapter X-Y`。
- 可選擇在整合成功後清除已整合來源，只保留範圍內最後一個資料夾及新輸出。
- 偵測章節 `result` 資料夾，翻譯圖片涵蓋所有原圖後才能封裝為 Komga 可讀取的 CBZ；只有 `result`、沒有原圖的既有章節仍可匯出。
- 支援自然排序、Unicode 路徑、增量跳過／更新、原子替換及批次錯誤隔離。
- 手動清空 `mask`、`inpainted` 內容；Komga 整批匯出成功後自動清理。
- 大型目錄掃描、漫畫整合、CBZ 匯出與清理皆在背景執行。

## 下載

從 [GitHub Releases](https://github.com/Honguan/Comic-sorting/releases/latest) 下載最新的 Windows x64 EXE。程式不依賴 WinRAR、7-Zip 或外部壓縮工具。

## 使用方式

介面支援繁體中文、English 與日本語。在視窗上方選擇語言會自動儲存，重新啟動後套用至按鈕、狀態、進度及提示訊息；BallonsTranslator 原生視窗的語言由它自己的設定控制。

1. 啟動 `Comic sorting.exe`。
2. 選擇漫畫路徑；可直接選擇包含多個系列的高層級目錄。
3. 在樹狀列表選擇父系列或章節，確認起始與結束編號後執行整合。
4. 翻譯工具完成 `result` 圖片後，按「重新掃描」。
5. 設定 Komga 輸出路徑，匯出選取項目或所有已翻譯項目。

上方漫畫列表支援搜尋與 Ctrl／Shift 多選，搜尋後選取系列只包含目前顯示的章節；重新掃描會保留仍存在的選取項目與展開狀態。整合範圍預設為選取章節的起訖編號，跨系列不可整合；匯出可同時選取多個系列。

搜尋列的「排序設定」可選系列更新時間、名稱、資料夾大小或章節數，搭配升冪／降冪；按「套用」立即排序並保存，重啟後沿用。預設更新時間由新到舊，欄位箭頭顯示目前方向；更新時間取該系列最新章節時間，大小為各章節合計，名稱採自然排序（2 在 10 前）。章節維持話數排序，整合編號不變；套用排序保留目前選取、展開狀態與手填整合範圍。

Ctrl＋F 可移到搜尋欄，Esc 或「清除搜尋」清空查詢。連續輸入會等待 180 毫秒再更新列表。上下區域間的分隔線可拖曳調整大小，小視窗會優先保留開始／停止與其他操作按鈕。

整個程式視窗可拖曳右下角的調整大小握把或視窗邊框放大／縮小，也可使用右上角的最大化按鈕；清單會隨視窗大小延伸。正常關閉時會記住視窗尺寸與最大化狀態，下次啟動還原；最小化不會覆蓋一般視窗尺寸。

整合的起訖編號指列表中的順序編號。選取父系列或單一章節時可以調整範圍；Ctrl／Shift 複選多個章節時只整合實際選取項目，範圍欄位會停用。請選擇不重疊的來源，例如複選 `Chapter 1-45` 與 `Chapter 46` 會產生 `Chapter 1-46`；不要把已包含在合併範圍內的 `Chapter 45` 再選入。只選取既有合併輸出時會沿用它，保留翻譯結果。若以原始章節重建同名輸出，確認視窗會提示覆寫其中的翻譯結果；任一來源沒有原圖時，整合會停止並保留來源。

下方分為「主佇列」「Komga 匯出」「設定」三個分頁，漫畫列表持續顯示。BallonsTranslator 路徑與原生設定入口位於「設定」。

輸出結構：

```text
D:\Komga\
└─ Series Name\
   ├─ Chapter 1.cbz
   └─ Chapter 2-10.cbz
```

CBZ 根目錄只包含 `result` 內的 `.png`、`.jpg`、`.jpeg`、`.webp` 圖片，不會重新編碼或壓縮圖片。

## BallonsTranslator 佇列

- 佇列摘要的「待翻譯檔案」顯示等待中翻譯項目的來源圖片總數；指定翻譯頁數時只計算該範圍。開始處理後會從等待數扣除，匯出／清理工作不計入此翻譯圖片數。加入、移除、重試、修改頁數、開始佇列或重新掃描時會重新計算；路徑無法讀取、沒有可翻譯圖片或頁數無效時會標示無法計數的項目數。

- 設定安裝路徑、既有 config JSON；Python 留白時依序尋找安裝目錄的 `ballontrans_pylibs_win/python.exe`、`.venv/Scripts/python.exe`，其他環境可指定其 Python。手動指定的 Python 優先使用。
- 新設定的安裝路徑留空，請先瀏覽選擇；既有設定會保留，選擇安裝目錄時會帶入其 `config/config.json`。
- 「開啟原生設定介面」直接啟動 BallonsTranslator，設定模型、OCR、翻譯器及排版後儲存並關閉，再開始佇列。環境、模型及工具均使用該安裝。
- 「編輯設定檔」可直接在 Comic sorting 內編輯所選 config JSON，詳見下方說明。
- 上方列表支援 Ctrl／Shift 多選，選擇「翻譯」「匯出」「清理」後加入佇列，也可逐次加入指定章節路徑。相同路徑與動作不重複加入。
- 雙擊上方章節列可直接將該章節加入主佇列，沿用目前選擇的動作；雙擊系列列仍是展開／收合，空白處不會加入。工作執行期間不可加入。
- 主佇列可右鍵選擇「移除佇列項目」，確認後移除並保存；只移除佇列紀錄，漫畫檔案會保留。右鍵點選未選取的列會切換到該列，點在多選項目內則保留多選；標題與空白處不開啟選單，工作執行期間停用移除。
- 上方漫畫列表可右鍵「刪除系列資料夾…」或「刪除章節資料夾…」，只針對右鍵點擊的那一列。確認視窗會列出完整路徑與範圍，預設選擇「否」；確認後**移至 Windows 資源回收筒**，可從資源回收筒還原。刪除系列包含其下所有章節，即使搜尋時未顯示；成功後才會移除相關佇列項目並重新掃描。無法回收或取消時會回報失敗，不自動改成永久刪除。掃描／工作執行期間不可刪除，也不可刪除漫畫根目錄或包含符號連結／目錄連接點的資料夾。
- 在主佇列選取**單一翻譯項目**，按「翻譯頁數」設定起始／結束頁（包含兩端）；多選、匯出／清理項目與執行期間不可設定。預設「全部頁面」，結束頁留白表示到最後；頁碼從 1 起算，按圖片檔名自然排序，並非檔名中的數字。各項範圍獨立保存；修改範圍後該項回到「等待」。
- 指定頁數可獨立勾選「指定頁面完成後匯出 CBZ」，**預設不匯出**，不受主佇列的全域匯出勾選控制；每筆工作保存自己的選擇，舊的指定頁數工作也預設不匯出。改回「全部頁面」則沿用主佇列的匯出設定。
- 指定範圍使用原生頁面選擇流程，只處理所選頁面，保留範圍外的圖片與翻譯；四階段進度的總頁數改為本次選取頁數。指定頁面完成即可算該項成功；全章 `result` 尚未齊全時略過自動匯出與清理，原因可在工作詳情查看。勾選匯出且全章結果齊全時，沿用整章 CBZ 匯出。需要支援 `pages_to_process` 的 BallonsTranslator 版本。
- 翻譯工作須至少啟用一個原生處理階段；全部關閉時會提示設定錯誤，避免原生無任務流程停留不退出。
- 主佇列依序處理；可選翻譯成功後匯出 CBZ、成功後清理 `mask`／`inpainted`。任一步驟失敗會跳過該路徑的後續動作，其他路徑繼續。
- 主佇列的「完成後開啟資料夾」**預設關閉**，選擇會保存並於重啟後還原。勾選後，每個翻譯工作及勾選的後續動作成功時開啟 Windows 檔案總管：未匯出時開啟 `result` 資料夾；已匯出時選取完成的 CBZ（包含增量沿用的檔案）。失敗或停止時不會開啟；開啟失敗會提示路徑並記錄日誌，不影響工作完成狀態。
- 「整合＋加入佇列」使用目前選定系列的起訖範圍，整合完成後只將輸出加入翻譯佇列等待，不會自動開始。按「開始主佇列」後才檢查翻譯設定、確認後續清理並執行佇列。
- 主佇列顯示工作完成數；BallonsTranslator 的文字偵測、OCR、修補與翻譯各有獨立進度條，同時顯示百分比、已處理頁數／總頁數與預估剩餘時間，例如 `55%｜417/755 頁｜剩餘 33:36`。頁數與 ETA 直接取自原生進度輸出，隨頁面處理更新；尚未取得速度時顯示「估算中」，未啟用的階段顯示「未啟用」，停止／失敗時保留已處理頁數並更新狀態。每個新工作會重設四條進度，匯出進度另外顯示。停止會終止目前翻譯程序，佇列匯出會在下一張圖片檢查取消並保留既有 CBZ，清理則完成當前步驟後停止。
- 工作狀態更新時會儲存，重新開始只執行「等待」項目；已保存的完成工作不會重跑。程式中斷後，上次執行中的項目顯示「已停止」，請先確認結果再「重試選取」。保存失敗會要求停止目前佇列。可上移／下移、重試選取、清除已完成；再次主動加入相同路徑與動作會將該工作重設為等待，不新增重複列。
- 主佇列與歷史紀錄的資料夾列顯示「錯誤碼」「錯誤原因」，雙擊佇列項目可查看完整路徑、分類與原始錯誤，包括致命錯誤摘要、翻譯程序最後 20 行輸出與 log 路徑。錯誤碼分類及限制見[錯誤碼說明](ERROR_CODES.md)。重試會清空當前列的舊錯誤，既有歷史保留；失敗或停止的前置工作須先重試，才能繼續同路徑的後續工作。翻譯以單一路徑清單啟動，支援含逗號的系列與章節名稱。

## 編輯 BallonsTranslator 設定檔

在「設定」指定 BallonsTranslator 安裝目錄、Python 與既有 config JSON，按「編輯設定檔」。欄位依所選安裝的 [BallonsTranslator 設定定義](https://github.com/dmMaze/BallonsTranslator/blob/dev/ballontranslator/utils/config.py) 及原生模組參數產生，不需啟動模型或連線呼叫 API。

- 左側可搜尋中文名稱或原始欄位名稱；展開物件與清單即可編輯所有已保存欄位、原生預設欄位及自訂模組參數。既有未知欄位會保留。涵蓋自動化流程、偵測／OCR／翻譯／修補器、LLM 配置卡與上下文、字體排版與文字特效、繪圖工具、拼寫檢查、取代規則、輸出格式、套件與鏡像，以及介面等進階設定。
- 布林值使用核取方塊；數字保持數值型別；模型／語言與模組選項使用下拉選單；提示詞支援多行文字；檔案路徑可瀏覽選取。自訂模型名稱可直接輸入，並同步加入該配置卡的模型選項。
- LLM 配置卡、取代規則、文字特效與變形可從原生範本新增；清單可複製、排序、移除，其他物件可新增指定型別的欄位。配置卡 ID 必須唯一，仍被選用的配置卡不能直接刪除而留下無效參照。
- API 金鑰預設遮蔽，留白保留原值，輸入新值取代，勾選清除才會刪除。新的 LLM 金鑰使用 BallonsTranslator 原生可攜式保存格式；既有保存格式保持不變。設定內容與金鑰不寫入應用程式日誌。
- 「需要 API 金鑰」（`require_api_key`）是核取開關，可直接啟用／停用；金鑰內容仍另行保存及遮蔽。
- 點選其他欄位會套用編輯中的值；「儲存設定檔」或 Ctrl＋S 才寫入檔案。先完成型別及原生設定檢查，再建立同目錄的 `config.json.<時間>.bak` 備份並原子替換。檔案被其他程式修改時拒絕覆蓋，須重新載入。關閉視窗時可儲存、放棄或取消。
- `finish_code` 由流程開關計算；新版文字特效的舊版相容欄位顯示為唯讀，請改用 `global_fontformat → text_effects` 編輯實際生效的設定。
- 先儲存並關閉設定編輯器，再啟動翻譯。編輯器與從本工具啟動的原生設定介面不可同時使用；既有原生設定入口仍可用。

設定編輯器需要所選 BallonsTranslator 的 Python 能載入其設定與靜態模組定義。安裝或 Python 路徑不正確、設定 JSON 損壞時會顯示錯誤並保留原檔。

## 日誌與失敗判斷

- 「各階段進度」與「本次佇列 LLM 消耗」可點擊標題按鈕各自收合／展開，每次啟動預設收合。展開時優先向上移動分隔線，縮小「漫畫整合」區以保留佇列表格高度；收合時歸還實際借用的高度。小視窗會保留上方操作欄，漫畫列表可縮至最小，空間仍不足的部分才由佇列區調整；仍可手動拖曳分隔線。執行途中也能切換；收合後仍持續更新進度、耗時與用量，展開即可查看最新數值。

- 顯示本次佇列總耗時，以及文字偵測、OCR、修補、翻譯的累計耗時（時:分:秒）。總耗時包含啟動、等待、匯出及清理；階段耗時採用翻譯器進度日誌，包含等待且可能互相重疊，不能相加當作總耗時。未回報顯示「—」，結束後保留數值，下次開始佇列時清空。

- Token 數使用 K／M／B 縮寫（不足 1,000 顯示整數）；金額先累計原始數值，再向上進位到小數第 2 位。OCR、翻譯與合計分列顯示，合計不使用已進位的分項金額相加。

- 主佇列最下方顯示本次執行的 LLM OCR、翻譯及合計 tokens、請求數與預估美元金額。直接採用 BallonsTranslator 的用量摘要，多個工作累計；合計不重複加入 OCR／翻譯分項。下次開始佇列時清空，未回報或估價不完整會明確標示；金額是翻譯器提供的等值估算，並非實際帳單。

- EXE 同目錄的 `logs/comic-sorting.log` 記錄啟動、掃描、整合、匯出、清理、設定保存失敗與介面例外。可從「設定 → 開啟紀錄資料夾」開啟。
- 每批佇列有獨立識別碼，記錄工作路徑／動作、BallonsTranslator 啟動命令與工作目錄、PID、標準輸出／錯誤輸出、退出碼、重試診斷、結果檢查與最終狀態。
- log 採 UTF-8，每檔最多約 10 MB，保留 3 個輪替備份（`.1`～`.3`）。不記錄設定檔內容，常見金鑰、Authorization、密碼與 access token 會遮蔽，包含 `OPENAI_API_KEY` 等帶前綴的欄位；日誌仍包含漫畫路徑與翻譯器輸出，分享前請檢查內容。
- BallonsTranslator 會在 LLM 回應格式錯誤、準備內建重試時先記一筆 `ERROR`。這個已知重試診斷不直接造成整批失敗。若已有流程結束標記、回報的各階段均完成且所選頁面輸出齊全，即使出現錯誤紀錄或退出碼異常，也列為「完成（有異常）」並保留工作詳情；可重試，也計入完成數。中途停止、階段未完成、缺少結束標記或缺少所選頁面的輸出，仍判為停止／失敗。
- `exit=0` 只代表程序正常退出，不代表每頁成功。例如 `LLM output limit reached` 會中止翻譯流程，即使程序最後仍顯示完成所有目錄，也必須先處理對應模型設定或回應問題。

## 歷史紀錄

- 主畫面的「本次佇列 LLM 消耗」累計本次所有資料夾的已回報用量，開始下一批時重設；歷史紀錄中的每批合計使用相同計算方式，金額先加總原始值再向上進位。
- 部分工作失敗或缺少估價時，仍加總所有已知金額（包含翻譯器的已計價小計），並標示「僅含已知金額」；只有完全沒有可用金額才顯示「無法預估」，已回報的零元照常顯示 `US$0.00`。舊歷史若在已保存的錯誤內容中留有相符用量摘要，讀取時補回小計供顯示，不改寫歷史檔，也不推算未回報費用。
- 點主佇列底部的「歷史紀錄」，可依漫畫名稱／路徑及開始日期範圍查詢；每次顯示最近 200 筆符合條件的佇列紀錄。佇列與資料夾預設摺疊；展開佇列查看各資料夾合計，再展開資料夾查看 OCR／翻譯／合計用量與耗時。選取佇列顯示整批摘要；選取資料夾或其分項顯示該資料夾的時間、頁數、用量、估價依據及執行結果。
- 從此版本開始記錄每次佇列及各項工作的開始／完成時間、耗時、狀態、翻譯頁數、OCR／翻譯／合計 Token、預估金額、請求數與各階段耗時。Token 以 K／M／B 顯示，金額向上進位到小數第 2 位；保留原始數值，不把 OCR／翻譯分項再次加到合計。未回報或估價不完整會明確標示，金額不是實際帳單。
- 每完成一個項目及整次佇列結束時儲存，失敗／停止也保留已回報資料；異常退出時，已保存但未收到結束事件的紀錄標示「未結束」。儲存失敗會提示並要求停止佇列。耗時由背景工作計時，階段耗時可能重疊，不能相加當作總耗時。
- 歷史存放於 EXE 同目錄的 `comic-sorting.history.sqlite3`，重啟及清除佇列不會刪除歷史；移動程式時請一併保留此檔。歷史不儲存 API 金鑰或翻譯器設定，也不會自動回補舊日誌。

## ntfy 手機／跨裝置通知

開啟「ntfy 通知」分頁設定。自動通知預設關閉；啟用後預設通知整批結束、單項失敗／異常，單項成功預設不通知。

1. 手機安裝 ntfy，或在其他設備開啟 ntfy 網頁。
2. 程式中的伺服器預設 `https://ntfy.sh`，也能使用自架伺服器根網址。主題會自動產生隨機名稱；按「複製訂閱網址」，在設備上訂閱同一伺服器及主題。不要將主題貼到「伺服器網址」欄。
3. 使用受保護主題時，填入具有發布權限的存取權杖；接收端也要具備訂閱權限。權杖僅透過 HTTPS 傳送，使用 Windows 當前使用者加密後保存；換電腦／Windows 帳號若無法解密，須重新輸入。單純填入權杖不會將公開主題變成私人主題。
4. 按「測試通知」確認接收，再勾選「啟用通知」和所需事件，按「儲存通知設定」。修改欄位後須按儲存才套用；測試通知使用畫面上的設定，無須先啟用自動通知。

單項通知在工作（包含已勾選的匯出／清理）結束、用量與耗時回報後發送，包含漫畫／章節、動作、時間、錯誤分類碼與原因、OCR／翻譯／合計用量。整批通知包含完成／異常／失敗／略過／停止／未執行數量、開始與完成時間、總耗時及累計用量；金額沿用向上取兩位小數，並標示非實際帳單。公開通知不傳送完整本機路徑、原始日誌或 API 金鑰。

同一次執行的重複事件不重送；主動重試工作屬於新一次執行。通知在獨立背景執行緒依序發送，不阻擋 UI 或翻譯。每次 HTTP 等待上限為 10 秒；429／5xx 最多重試一次，尊重短時間的 `Retry-After`，較長等待交由使用者處理。網路逾時／斷線可能發生在服務已接收之後，因此不盲目重送。服務錯誤重試仍可能產生重複通知，不能保證嚴格只送達一次。

發布請求使用明確的 `Comic-sorting` User-Agent，避免自架伺服器的代理將 Python 預設識別擋下。Cloudflare 1010 會另列錯誤碼；一般 HTTP 403 也可能來自代理／防火牆，不直接判定為權杖缺少發布權限。

分頁顯示最後的通知結果，日誌只記錄通知結果碼，不記錄主題、權杖與通知內容：

| 通知結果碼 | 意義 |
|---|---|
| `NTFY_OK` | ntfy 伺服器確認接收；不代表手機已顯示或已讀 |
| `NTFY_CONFIG`／`NTFY_TOKEN` | 設定無效，或權杖保護／解密失敗 |
| `NTFY_HTTP_401`／`NTFY_HTTP_403` | 權杖無效／缺少，或請求遭拒絕；403 須檢查 ntfy 權限及代理／防火牆規則 |
| `NTFY_CLOUDFLARE_1010` | Cloudflare 阻擋用戶端識別，並非 ntfy 權杖權限判定 |
| `NTFY_HTTP_404` | 伺服器網址不存在 |
| `NTFY_HTTP_429`／`NTFY_HTTP_5xx` | 通知頻率／額度限制，或遠端服務錯誤（5xx 顯示實際數字） |
| `NTFY_NETWORK`／`NTFY_RESPONSE` | 連線失敗／逾時，或回應並非有效的 ntfy 發布結果 |
| `NTFY_QUEUE_FULL`／`NTFY_INTERNAL` | 背景待送數量達上限，或通知程式發生異常 |

通知失敗不改變翻譯結果、不停止主佇列。未送完的通知只存在記憶體，關閉程式不會保證補送；目前不包含長時間無進度、程式崩潰、電腦關機或斷網的外部監控。手機需允許 ntfy 的通知權限，並依平台設定背景接收。

API 與主題規格：[ntfy 官方發布文件](https://docs.ntfy.sh/publish/)；私人主題：[存取控制](https://docs.ntfy.sh/config/#access-control)。

## 清理注意事項

「整合後清除來源」與「保留最後一個」可分別勾選，兩者都會記錄在可攜式設定 JSON。清除來源預設關閉，保留最後一個預設開啟，舊設定沿用原本保留最後一個的行為。啟用清除來源後，勾選保留會留下本次選取範圍內的最後一個來源資料夾；取消勾選則會清除本次選取的全部來源，但整合輸出一律保留。沒有啟用清除來源時，所有來源都會保留。

確認視窗會顯示對應的清除範圍；刪除只在整合成功後執行，且無法復原。

「清理所有 mask / inpainted」會清空目前漫畫路徑下所有同名資料夾的內容，但保留資料夾本身。手動清理前會要求確認，操作無法復原。

Komga 匯出會在狀態檔保存成功後，自動清理實際匯出成功章節的工作資料；未選取或匯出失敗的章節不會被清理。

## 路徑綁定與增量狀態

- 可攜式設定：EXE 同目錄的 `comic-sorting.settings.json`
- Komga 增量狀態：`<Komga 路徑>\.comic-sorting-state.json`

首次啟動時漫畫與 Komga 路徑皆為空白，必須手動設定。設定後會自動保存並在後續啟動時讀取；重新瀏覽即可改綁其他路徑。移動 EXE 時請連同設定檔一起移動。

手動輸入有效漫畫路徑後按 Enter／重新掃描也會保存；兩個匯出選項會在重啟後保留。掃描不進入 `result`、`mask`、`inpainted` 與整合暫存／備份目錄尋找章節，也不追蹤目錄連結；資料夾大小不計入連結指向的外部內容。

增量狀態依圖片名稱、大小及修改時間判斷來源是否變更，並檢查 CBZ 大小與修改時間。CBZ 被改動時重新建立；舊版狀態首次沿用 CBZ 前會驗證內容。不同來源的同名系列／章節若會覆蓋已記錄的輸出，會明確報錯，請改用不同的 Komga 路徑或系列名稱。

設定、翻譯器 config 或匯出狀態 JSON 若損壞、根層不是物件或無法讀取，程式會指出檔案路徑並停止相關操作，保留原檔。請檢查權限、修正 JSON，或還原已知完好的備份後重試；不會把壞檔當成空設定覆寫。首次使用尚無設定／狀態檔仍採預設值，並支援 UTF-8 BOM。

JSON 與 CBZ 使用同目錄的唯一暫存檔，完成後原子替換。Windows 暫時鎖定目標檔時會短暫重試（最多 6 次嘗試，等待合計 0.62 秒）；持續鎖定或權限錯誤仍會回報，請關閉占用檔案的程式或檢查寫入權限後重試。這能避免暫存檔互相干擾，但沒有提供多個 EXE 同時修改同一設定、漫畫或 Komga 狀態的交易／合併功能，請一次使用一個操作實例。

## 開發與建置

- `comic_core.py`：圖片、CBZ、JSON 與清理等共用檔案操作。
- `queue_worker.py`：穩定的工作／狀態代碼、BallonsTranslator 子程序及佇列執行；以事件回傳結果，不操作視窗。
- `translation_queue.py`：佇列介面、排序、重試及狀態保存。
- `bt_settings.py`：完整設定欄位編輯、型別檢查、備份及存檔衝突檢查；`bt_config_bridge.py` 使用所選翻譯器環境讀取定義、檢查設定與保存金鑰。
- `Comic sorting.py`：漫畫列表、整合與主視窗協調；`ui_language.py` 管理三語文字。

需求：Python 3.10、PyInstaller 6.22.2；Windows 資源回收筒使用 `pywin32==312` 呼叫原生 Shell 介面。EXE 已內含依賴，使用者不需另外安裝；PyInstaller 只用於建置。

```powershell
py -3.10 -m pip install -r requirements.txt pyinstaller==6.22.2
py -3.10 -B -m unittest discover -s tests -v
py -3.10 -m PyInstaller --clean --noconfirm "Comic sorting.spec"
```

建置輸出位於 `dist\Comic sorting.exe`。推送 `v*` 標籤時，GitHub Actions 會執行測試、建置並建立 Release。
推送 `main` 或建立 Pull Request 時，唯讀 Verify workflow 也會執行測試及建置，不會發佈 Release。
