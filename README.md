## 安裝與開始使用

1. 從 [GitHub Releases](https://github.com/Honguan/Comic-sorting/releases/latest) 下載 Windows x64 EXE，放在可寫入的資料夾後啟動。
2. 選擇漫畫根目錄，按「重新掃描」載入系列與章節。
3. 要翻譯，在「設定」指定另行安裝的 BallonsTranslator 及其 `config/config.json`。Python 留白會尋找該安裝的內附環境或 `.venv`。
4. 要匯出 CBZ，在「Komga 匯出」設定輸出目錄。
5. 選擇章節與動作，加入主佇列，再按開始。

EXE 已包含本工具依賴，不需額外安裝 Python 或壓縮軟體；BallonsTranslator、模型與翻譯服務需另外準備。介面支援繁體中文、English、日本語，切換後重新啟動套用。

## 常用操作

| 操作 | 行為 |
|---|---|
| 整合章節 | 選取同一漫畫的章節與範圍；自動略過已整合資料夾。 |
| 加入佇列 | 選擇翻譯、匯出或清理，再加入所選項目或指定路徑；雙擊上方章節也可加入。 |
| 依編號加入佇列 | 使用列表起始／結束序號，結束留白代表到最後；只加入，不整合、不自動開始。 |
| 整合＋加入佇列 | 整合完成後將輸出加入翻譯佇列，等待手動開始。 |
| 開始 | 有選取：只執行所選章節或群組內的等待工作；沒選取：依原順序執行全部等待工作。 |
| 調整順序 | 上移、下移、移到最上／最下；多選時保留原本先後順序。 |
| 暫停／繼續 | 目前資料夾及其後續匯出、清理完成後暫停，再按繼續接著處理同一批次。 |
| 停止 | 中止目前處理，保留後續等待項目；重新啟動程式不會自動續跑。 |
| 重新選取 | 有選取：重設範圍內的失敗、異常、已停止、阻擋工作；沒選取：重設全部失敗／異常。已完成項目只有單獨選取該工作列時才能重排。 |
| 翻譯頁數 | 選取單一翻譯工作，設定含首尾的頁數範圍；依圖片檔名自然排序，從第 1 頁起算。 |
| 搜尋與檢視 | 搜尋漫畫名稱或路徑；群組顯示單一／整合章節數及翻譯頁數。「放大佇列」可擴大工作區。 |
| 名稱與路徑 | 匯出全部漫畫名稱；右鍵複製漫畫名稱或完整路徑。 |

- **搜尋只影響顯示。** 若要只跑搜尋結果，須先選取；沒選取仍執行全部等待工作。
- 開始選取項目時，單一漫畫有多個待翻譯單一章節會詢問起訖，預設從頭到尾，整合章節仍照常執行；直接選章節不詢問。多個漫畫不問範圍，改顯示漫畫優先順序，可拖曳或上下移動；預設保留原佇列順序，調整只影響本批次，取消不開始。
- 再次加入相同路徑與動作會將既有工作重設為等待；重新選取不會自動開始。執行及暫停期間不能新增或重排工作。
- 列表支援 Ctrl／Shift 多選、Ctrl＋A 全選、Esc 取消選取、Ctrl＋C 複製路徑。搜尋中的群組選取僅包含顯示項目。
- 點擊漫畫列表欄位標題排序；視窗可最大化，上下區域可拖曳分隔線調整。

### 翻譯、匯出與紀錄

- 「主佇列 → 排程啟動」可新增多筆倒數分鐘或固定日期時間的一次性排程。建立時確認選取範圍、章節及順序；到時只執行原選取中仍等待且未變更的工作，忙碌或暫停時等待空閒。變更翻譯／清理／輸出設定須重新排程。程式需保持開啟，關閉即取消，不會喚醒或自動開機。
- 多章翻譯共用同一個 BallonsTranslator 程序，逐章完成結果檢查、匯出、清理與保存後才交付下一章。暫停保留模型與 GPU 佔用；停止或整批結束關閉程序，翻譯失敗後下一章重建程序。不修改 BallonsTranslator 原始碼，Codex 每次請求的連線方式仍由翻譯器決定。
- 「編輯設定檔」可修改運行選項、目前模組與翻譯字體；保留未顯示欄位，儲存前驗證、備份並檢查外部修改。
- 指定頁數需要 BallonsTranslator 支援原生頁面選擇。範圍成功不代表整章完成；全章結果不足時略過自動匯出及清理。範圍工作的匯出須另外勾選。
- CBZ 使用 `result` 圖片，輸出為 `<Komga 目錄>/<漫畫名稱>/<章節>.cbz`；檢查結果完整性，未變更內容可增量略過。
- 各階段顯示進度、剩餘時間及平均秒／頁；用量與歷史以欄位顯示，Token 使用 K／M／B。金額是已回報用量的估算，**不是實際帳單**；未回報及不完整資料會標示。
- 「通知」可分別啟用 Windows 與 ntfy。通知失敗不停止工作；伺服器接收成功不代表手機已顯示。

## 資料與注意事項

| 資料 | 位置 |
|---|---|
| 設定、佇列與偏好 | EXE 同目錄的 `comic-sorting.settings.json` |
| 歷史紀錄 | EXE 同目錄的 `comic-sorting.history.sqlite3` |
| 日誌 | EXE 同目錄的 `logs/comic-sorting.log` |
| Komga 增量狀態 | `<Komga 目錄>/.comic-sorting-state.json` |

- 移動程式時一併保留設定與歷史。**一次只開一個操作實例**，避免覆蓋相同設定或匯出狀態。
- 移除佇列項目不刪除漫畫；上方列表右鍵刪除資料夾會移至 Windows 資源回收筒。
- **整合後清除來源、清理 `mask`／`inpainted` 為永久刪除。** 整合可保留最後一個來源；手動 Komga 匯出在狀態保存成功後清理成功章節的工作資料，佇列則依清理選項執行。
- 類型依名稱判斷：`Chapter 1` 為單一章節，`Chapter 1-30` 為整合資料夾；改名可能影響分類。
- 設定或狀態檔損壞時停止相關操作並保留原檔，請修復或還原備份。日誌可能包含路徑及翻譯器輸出，分享前請檢查。

## 開發與建置

Windows、Python 3.10；沿用專案固定依賴：

```powershell
py -3.10 -m pip install -r requirements.txt pyinstaller==6.22.2
py -3.10 -B -m unittest discover -s tests -v
py -3.10 -m PyInstaller --clean --noconfirm "Comic sorting.spec"
```

輸出：`dist/Comic sorting.exe`。GitHub Actions 對 `main` 與 PR 執行測試及建置，`v*` 標籤觸發 Release。

核心檔案：`Comic sorting.py`（主視窗）、`comic_core.py`（檔案操作）、`queue_worker.py`（工作執行）、`translation_queue.py`（佇列介面）、`queue_history.py`（歷史）。
