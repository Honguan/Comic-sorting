## 安裝與開始使用

1. 從 [GitHub Releases](https://github.com/Honguan/Comic-sorting/releases/latest) 下載 Windows x64 EXE，放在可寫入的資料夾後啟動。
2. 選擇漫畫根目錄，按「重新掃描」載入系列與章節。
   掃描建立記憶體頁數索引，供佇列共用；重新掃描或重開程式時重建。外部增刪圖片後請重新掃描。
3. 要翻譯，在「設定」指定另行安裝的 BallonsTranslator 及其 `config/config.json`。Python 留白會尋找該安裝的內附環境或 `.venv`。
4. 要匯出 CBZ，在「Komga 匯出」設定輸出目錄。
5. 選擇章節與動作，加入主佇列，再按開始。

EXE 已包含本工具依賴，不需額外安裝 Python 或壓縮軟體；BallonsTranslator、模型與翻譯服務需另外準備。介面支援繁體中文、English、日本語，切換後重新啟動套用。

## 常用操作

左側「漫畫庫」選取漫畫，填寫從 1 起算的章節列表序號，再按「加入區間」；指定章節可用多選與「加入選取」。右側選擇處理動作與流程，按「開始執行」。整合移到「章節整合」分頁，匯出／清理偏好集中在「選項」，重排／重試／排程集中在「更多操作」。

預設使用較大的字體；窄視窗只保留名稱、頁數及狀態等主要欄位，選取後仍可查看完整路徑與資料。「各階段進度」與「本次佇列 LLM 消耗」開啟獨立視窗，主畫面保留清單與本次耗時；放大／還原佇列使用連續動畫。漫畫庫先顯示系列，展開時才建立章節列，掃描共用目錄列舉結果並顯示讀取數與耗時。

主佇列開始按鈕旁的「▼」選單提供五種流程；選擇模式後再按開始。選取範圍規則不變。

| 流程 | 處理方式 |
| --- | --- |
| 原本流程 | 每章依原生設定完成偵測、OCR、修補與翻譯。 |
| 只跑前處理 | 偵測、OCR、修補後保存檢查點，不渲染翻譯結果、匯出或清理。 |
| 只翻譯已前處理 | 檢查來源與前處理成果，再翻譯；缺少或變更的成果會略過。 |
| 先全部前處理再翻譯 | 先完成第一輪，關閉程序釋放模型，再開始翻譯。 |
| 前處理與翻譯並行 | 兩個程序跨章節接力；前處理下一章時，可翻譯已保存的上一章。 |

- 可分開執行兩輪或重開後再翻譯。完成的前處理存於各章節 `.comic-sorting-prepared.json`；只翻譯模式會檢查來源、OCR 與修補成果，缺少或已變更就略過。舊資料沒有本工具完成紀錄時須先跑前處理。已完成的佇列項目不會自動重跑；失敗／停止項目需重新選取。若 OCR 或修補選用雲端服務，前處理仍會使用該服務。

| 操作 | 行為 |
|---|---|
| 整合章節 | 「章節整合」分頁選取同一漫畫的章節與範圍；自動略過已整合資料夾。 |
| 加入佇列 | 選擇翻譯、匯出或清理，再按漫畫庫「加入選取」或加入指定路徑；雙擊章節也可加入。 |
| 加入區間 | 使用列表起始／結束序號，結束留白代表到最後；只加入，不整合、不自動開始。 |
| 整合＋加入佇列 | 整合完成後將輸出加入翻譯佇列，等待手動開始。 |
| 開始 | 有選取：只執行所選章節或群組內的等待工作；沒選取：依原順序執行全部等待工作。 |
| 調整順序 | 上移、下移、移到最上／最下；多選時保留原本先後順序。 |
| 暫停／繼續 | 目前資料夾及其後續匯出、清理完成後暫停，再按繼續接著處理同一批次。 |
| 停止 | 中止目前處理，保留後續等待項目；重新啟動程式不會自動續跑。 |
| 更多操作 → 重試 | 有選取：重設範圍內的失敗、異常、已停止、阻擋工作；沒選取：重設全部失敗／異常。已完成項目只有單獨選取該工作列時才能重排。 |
| 選項 → 翻譯頁數 | 選取單一翻譯工作，設定含首尾的頁數範圍；依圖片檔名自然排序，從第 1 頁起算。 |
| 搜尋與檢視 | 搜尋漫畫名稱或路徑；群組顯示單一／整合章節數及翻譯頁數。「放大佇列」可擴大工作區。 |
| 名稱與路徑 | 匯出全部漫畫名稱；右鍵複製漫畫名稱或完整路徑。 |

- **搜尋只影響顯示。** 若要只跑搜尋結果，須先選取；沒選取仍執行全部等待工作。
- 開始選取項目時，單一漫畫有多個待翻譯單一章節會詢問起訖，預設從頭到尾，整合章節仍照常執行；直接選章節不詢問。多個漫畫不問範圍，改顯示漫畫優先順序，可拖曳或上下移動；預設保留原佇列順序，調整只影響本批次，取消不開始。
- 再次加入相同路徑與動作會將既有工作重設為等待；重新選取不會自動開始。執行及暫停期間不能新增或重排工作。
- 列表支援 Ctrl／Shift 多選、Ctrl＋A 全選、Esc 取消選取、Ctrl＋C 複製路徑。搜尋中的群組選取僅包含顯示項目。
- 點擊漫畫名稱標題依名稱排序；「工具 → 排序」可選更新時間、名稱、大小及章節數，同一欄位再次選取切換升／降冪。左右區域可拖曳分隔線調整。

### 翻譯、匯出與紀錄

- 「主佇列 → 更多操作 → 排程啟動」可新增多筆一次性排程。「倒數啟動」設定小時／分鐘或使用快捷按鈕；「指定日期時間」設定日期與時／分，可快速選今天／明天。新增前會預覽本機啟動時間，並確認選取範圍、章節及順序；到時只執行原選取中仍等待且未變更的工作，忙碌或暫停時等待空閒。變更翻譯／清理／輸出設定須重新排程。程式需保持開啟，關閉即取消，不會喚醒或自動開機。
- 多章翻譯共用同一個 BallonsTranslator 程序，逐章完成結果檢查、匯出、清理與保存後才交付下一章。暫停保留模型與 GPU 佔用；停止或整批結束關閉程序，翻譯失敗後下一章重建程序。不修改 BallonsTranslator 原始碼，Codex 每次請求的連線方式仍由翻譯器決定。
- 「前處理與翻譯並行」：兩個獨立程序各自跨章節重用；每章前處理完整存檔後，翻譯依佇列順序接手，前處理可繼續下一章。已驗證有效的前處理會跳過，失敗章節不交給翻譯。同一路徑重複排入會等待前一項翻譯完成，避免同時寫檔。暫停會等兩邊目前章節完成；停止會停止兩邊，重開後可依磁碟紀錄接續。前處理不匯出或清理，翻譯完成後才依設定執行；同時保留兩個程序會增加記憶體需求。
- 所有模組、模型、併行數、提示詞、字體與登入設定統一使用「開啟原生設定介面」修改；在 BallonsTranslator 儲存並關閉原生介面後，再開始佇列。本工具不再編輯原生設定檔。
- 支援 Jev 的安裝版本仍可回報原有統計；未提供 Jev 或未回報資料時保持空白／「—」，不影響處理，也不補算用量。Jev 開關與金鑰在該版本的原生介面設定。
- Jev 統計在每次 Jev 清理結束後更新處理／變更次數、清空／修剪／保留文字塊、移除字元及已回報耗時；新版 Jev 獨立顯示輸入 Token（K/M/B）、請求數及未回報輸入用量的請求數，讀取翻譯器回報的金額、來源（回報／估算）及未計價請求數，不混入 LLM 總用量；舊版 Jev 用量紀錄仍保留。新版 Jev 耗時包含於翻譯救援（舊版包含於 OCR），不再加進整批總耗時；舊歷史缺少資料顯示「—」，不推算補值。
- 佇列沿用安裝版本的原生流程，支援 `D:\AI\Ballonstranslator_win_minium` 的 Codex OCR／修補／翻譯跨頁併行；併行數、RPM／延遲與模型目錄均由原生模組管理，不再由本工具維護一份設定。前處理與翻譯跨章並行可與原生跨頁併行共同使用。
- Token 讀取官方逐次請求紀錄：以 `total` 為準，缺少時僅在輸入與輸出均回報後相加；OCR 只累加每次 `Used`，不累加跨章保留的 `Total`。快取與思考 Token 是子項，不重複加總；每次重試與記憶壓縮回報各計一次。舊版章節用量摘要會取代逐次累計，Jev 保持獨立。
- 所有模型共用計價：OpenAI 原生目錄 14 個模型內建官方 Standard 單價（核對日期 `2026-10-01`）；其他模型自動查詢 [OpenRouter 公開目錄](https://openrouter.ai/api/v1/models)，使用該目錄的 API 等值費率，支援 latest 別名、長上下文及尖／離峰級距。自訂／私人模型可在「設定 → 模型單價」輸入任意模型 ID 的每百萬 Token 美元單價，自訂值優先；快取留白使用輸入單價。本機 Ollama／LM Studio 的 API 費用按零計算，不含硬體與電費。
- OCR、翻譯及記憶壓縮逐次取得請求實際模型與輸入／輸出／快取用量，輸出達上限時仍記錄已回傳用量；沒有回傳用量的失敗請求保留模型及缺漏標記。橋接紀錄優先，避免再累加原生日誌。混合模型加總保留全部模型名稱，佇列用量與歷史明細均顯示；未計價請求也保存模型。模型快照 ID 不會改成其他版本的名稱或單價。
- 預估金額非實際帳單，不含未回報的修補用量、工具費及未回報的額外費用。快取與思考 Token 不重複計算，未回報快取數量暫按零估算；歷史保存模型、費率依據、來源、日期及套用單價。公開目錄離線或查無模型時可填自訂單價；缺少用量仍標記不完整，舊歷史不推算。原生已回報金額優先；無金額摘要僅在請求數、Token 與缺漏數吻合時保留本地估價。
- 指定頁數需要 BallonsTranslator 支援原生頁面選擇。範圍成功不代表整章完成；全章結果不足時略過自動匯出及清理。範圍工作的匯出須另外勾選。
- CBZ 使用 `result` 圖片，輸出為 `<Komga 目錄>/<漫畫名稱>/<章節>.cbz`；檢查結果完整性，未變更內容可增量略過。
- 各階段顯示進度、剩餘時間及平均秒／頁；用量與歷史以欄位顯示，Token 使用 K／M／B。金額是已回報用量的估算，**不是實際帳單**；未回報及不完整資料會標示。
- 佇列「統計 → 模型統計」與歷史明細「模型統計」頁籤集中顯示 OCR／翻譯／合計的各模型 Token、請求數、預估費用、輸入／輸出與快取分項，以及未計價／未回報請求。即時佇列與選取的歷史批次／章節共用欄位；費用顯示六位小數，儲存仍保留原始精度。合計已包含 OCR 與翻譯，快取是輸入的子項，不另外加總。舊紀錄只有單一已知模型時可歸入該模型；多模型缺少分項時顯示「模型未分項」，不推算分配。
- 模型統計提供 Token／請求／已知費用佔比及平均每次請求 Token／費用。佔比分別以 OCR、翻譯、合計的所有模型（含未分項資料）為基準，使用原始數值計算後才四捨五入至百分比兩位小數；分母為零時顯示「—」。平均 Token 排除未回報用量的請求，平均費用僅在金額完整時顯示，避免把未知費用當成零。
- 歷史介面分為「執行紀錄」、「選取項目明細」與「全部歷史總累計」；詳細總計預設收合，按「詳細統計」展開。每頁顯示 200 批，可用「上一頁／下一頁」查看其他紀錄；展開批次與章節才載入子項。重新整理保留目前頁面的展開與選取，變更查詢條件回到第一頁。全部總累計仍包含所有歷史與失敗／停止工作已回報用量，累計時只保留彙總資料。
- 完成數只計成功或完成含異常的工作，不計等待、失敗、停止及前處理完成待翻譯。已知金額合計若缺少任一筆費用，仍標示僅含已知金額。章節／階段耗時可互相重疊，不再加進整批實際耗時。
- 「通知」可分別啟用 Windows 與 ntfy。通知失敗不停止工作；伺服器接收成功不代表手機已顯示。

## 資料與注意事項

| 資料 | 位置 |
|---|---|
| 設定、佇列與偏好 | EXE 同目錄的 `comic-sorting.settings.json` |
| 歷史紀錄 | EXE 同目錄的 `comic-sorting.history.sqlite3` |
| 日誌 | EXE 同目錄的 `logs/comic-sorting.log` |
| Komga 增量狀態 | `<Komga 目錄>/.comic-sorting-state.json` |

- 移動程式時一併保留設定與歷史。同一設定檔只允許一個 Windows 實例，重複啟動會喚回既有視窗。更新後請先關閉所有舊版；舊版未具備此保護。不同安裝目錄仍可分開啟動，請勿同時操作相同漫畫或匯出目錄。
- 移除佇列項目不刪除漫畫；上方列表右鍵刪除資料夾會移至 Windows 資源回收筒。
- **整合後清除來源、清理 `mask`／`inpainted` 為永久刪除。** 整合可保留最後一個來源；手動 Komga 匯出在狀態保存成功後清理成功章節的工作資料，佇列則依清理選項執行。
- 類型依名稱判斷：`Chapter 1` 為單一章節，`Chapter 1-30` 為整合資料夾；改名可能影響分類。
- 設定或狀態檔損壞時停止相關操作並保留原檔，請修復或還原備份。日誌可能包含路徑及翻譯器輸出，分享前請檢查。

## 開發與建置

Windows、Python 3.10；沿用專案固定依賴：

```powershell
py -3.10 -m pip install -r requirements.txt pyinstaller==6.22.2
py -3.10 -B -m unittest discover -s tests -v
py -3.10 -m PyInstaller --clean --noconfirm "Comic sorting.spec"
```

輸出：`dist/Comic sorting.exe`。GitHub Actions 對 `main` 與 PR 執行測試及建置，`v*` 標籤觸發 Release。

核心檔案：`Comic sorting.py`（主視窗與事件）、`comic_core.py`（掃描、整合與檔案操作）、`queue_worker.py`（工作執行）、`translation_queue.py`（佇列介面）、`queue_stats.py`（快照合併及差額統計）、`queue_history.py`（歷史查詢與分頁）。五種流程共用原有工作執行器；設定與歷史資料格式不變。

效能量測：`py -3.10 -X utf8 benchmarks/benchmark_refactor.py`。只用合成資料，不執行翻譯；[重構與驗證報告](docs/refactor-2026-10-01.md) 記錄功能覆蓋、前後量測與限制。
