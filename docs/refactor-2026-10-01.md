# 全功能重構與驗證

範圍：功能邏輯、介面、功能說明、程式結構、效能與載入，以及歷史與統計。沿用 Python 3.10、Tkinter 與既有設定及 SQLite/JSON 格式，沒有新增執行期依賴。

基準為 `3b6decb`，原有 253 項測試通過。使用者歷史約 16 MB、47 批，設定含 4,096 個工作。交付只替換 EXE；設定及歷史以 SHA256 確認未變更。

## 結構與功能覆蓋

主視窗分開狀態初始化、漫畫面板與工作分頁；佇列分開設定面板、工作面板與工作還原。掃描、章節識別與整合移入共用檔案核心，保留原有類別入口。背景工作繼續以事件更新介面。

| 功能 | 保留與改善 | 回歸模組 |
| --- | --- | --- |
| 掃描／搜尋 | 自然排序、分類、大小／時間、頁數索引；搜尋只改顯示，共用檔案核心 | comic_sorting、improvements、ui_workflow |
| 整合 | 範圍、多選、重名、暫存／備份回復、保留最後來源；檔案操作與介面分開 | comic_core、comic_sorting、ui_workflow |
| 主佇列 | 新增、重排、重試、頁數、批次選取、前置工作阻擋、暫停／停止；事件批次只更新一次摘要與控制項 | translation_queue、queue_worker、ui_workflow |
| 五種流程 | 持久程序、前處理檢查點、跨章及原生跨頁並行、原生登入；共用快照合併 | queue_phases、queue_parallel、bt_run_bridge、queue_worker |
| 匯出／清理 | 完整性、CBZ 驗證、增量、原子替換、保存後才清理；狀態檔錯誤不多算失敗章節 | comic_core、comic_sorting、queue_worker、ui_workflow |
| 排程 | 多筆、倒數／日期、工作及設定快照、等待空閒、關閉取消；一次建立身分集合核對工作 | queue_schedule、ui_workflow、benchmark_refactor |

回歸模組對應 `tests/test_<名稱>.py`；量測另見 `benchmarks/benchmark_refactor.py`。已模組化的執行器、通知與刪除保護保留原實作；改善集中在共用資料流、介面初始化與實際瓶頸。

中英文 README 以表格說明五種流程，將並行說明移回翻譯章節，補上完成數、部分金額、重疊耗時及量測方式。

## 修正與證據

- 歷史 upsert 原本只更新 JSON，搜尋路徑仍舊；新回歸修正前失敗，現在時間、路徑與內容同步。
- 每頁 200 批，時間與資料列身分形成穩定排序。先建立批次列，展開才建立章節／用量列；重新整理保留展開與選取，查詢改變回第一頁，查詢錯誤保留原資料。
- 合計及未計價請求數不足以判斷金額完整性；快照及跨階段合併保留不完整標記。未知耗時不補零；Jev 與重疊階段耗時不重複加進整批時間。
- 手動匯出狀態檔保存失敗仍回報錯誤並阻擋清理，但不算成額外章節；兩章匯出不再合計成三項。
- 工具列拆成兩排曾造成內容超過第 683 像素、佇列表格被擠掉；保留單排與執行控制優先配置。三語 820×640、展開／收合及分隔線回歸通過。
- 預設啟動尺寸設於程式入口，避免覆寫外部已設定的 Toplevel 尺寸；已保存尺寸仍優先套用。

## 可重現量測

執行 `py -3.10 -X utf8 benchmarks/benchmark_refactor.py`。各取三次中位數；歷史與用量基準於修改前量測，排程基準使用 `3b6decb` 的原始模組。

| 合成場景 | 基準 | 修改後 |
| --- | ---: | ---: |
| 3 批 × 1,000 章節，開啟歷史 | 0.2187 秒／12,003 列 | 0.1149 秒／3 列 |
| 5,000 工作，100 次用量更新 | 0.3572 秒 | 0.0068 秒 |
| 5,000 工作，排程核對與交付 | 0.3020 秒 | 0.0015 秒 |

數字反映本機介面與統計成本，不代表 OCR、GPU 或翻譯 API 吞吐量。全部歷史總累計仍讀取所有批次；改善的是初始子列建立與大佇列重複計算，沒有刪除資料。
